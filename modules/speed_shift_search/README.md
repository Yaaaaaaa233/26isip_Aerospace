# 任务1：平移曲线上的瞬时跳变黑箱速度搜索

> 对应五任务路线（路线全文见仓库 `docs/TASKS_1_5_ROUTE.md`）的任务 1。
> 2026-09-01 ｜ 状态：16/16 单元测试、8/8 tracker 性能门槛通过

## 问题设定

把自己当成黑箱：操作一个**可以瞬时修改**的速度值（无惯性、无限速），
看到功率读数，目标是找到功率最小的速度。曲线会**上下左右平移**：
左右平移（Δx，最优速度漂移，如风/载荷/电量变化）是真挑战；上下平移
（Δy，功率整体偏移）不改变最优速度，算法不应被它误导。任务 1 无噪声
（噪声与多峰在任务 2 处理）。背景叙事是打破无人机悬停续航纪录——
**全程平均功率**每一分都计入成绩，因此寻优过程本身烧掉的电也算数。

对象为仓库既有代理曲线（三次文献代理/二次调试）的**严格平移**
`P(v,t) = P0(v − Δx(t)) + Δy(t)`，与 `+speedesc` 的"改 v* 再算 x"横向
缩放不同（有意选择：平移不变性便于考察算法）。

## 算法选型结论：tracker = Brent 混合搜索 + 锁定 + 平移监测重夹逼

**为什么不用 ESC 作为主方案**：任务 1 取消了执行动态，而 ESC 的核心
价值（穿越未知动态的连续扰动寻优）正依赖动态存在。ESC 收敛到邻域而非
点，扰动 `a=0.5` 带来约 ½P″(V*)·a² ≈ 0.18% 的**永久**功率超额——对
全程平均计分的续航纪录不利。可终止的直接搜索稳态零扰动代价。

**为什么黄金分割主干 + 抛物线加速**：无噪声单峰、瞬时执行设定下，
黄金分割是逐次评估意义最优的确定性搜索（Kiefer 1953；每评估一次区间
收缩 0.618）；抛物线插值在光滑段呈超线性收敛，混合后比纯黄金分割再省
约一半评估。**实测**（cubic 静态场景，入带 ε=0.05 m/s）：

| 算法 | 入带评估数 | 稳态超额% | 全程能耗%(跳变场景) |
|---|---:|---:|---:|
| 网格扫描(步长0.2) | 101(且只能保证±0.1) | 0.007 | 19.69 |
| 三分搜索 | 9 | 0.000 | 2.82 |
| 黄金分割 | 8 | 0.000 | 2.77 |
| **Brent混合** | **6** | 0.000 | 2.67 |
| **tracker(推荐)** | **6** | 0.030 | **0.21** |
| ESC(连续跟踪) | 45 | 0.097 | 0.64 |

基线（grid/ternary/golden/brent）是"搜索后锁定"策略——平移发生后不重
搜、停在过时最优点上（跳变后稳态超额 2.2–4.7%），这正是 tracker 监测
层的对照证据。ESC 能连续跟踪但恢复慢（68 步 vs tracker 14 步）且全程
能耗高 3 倍。

## 平移判别：斜率迟滞双阈值（核心设计）

锁定后每隔 `probePeriod` 步做两点复探 v̂±`probeDelta`，斜率
`g=(P⁺−P⁻)/(2δ)`：

- `|g| ≥ slopeThresh`(0.002) → 判定左右平移：以旧最优点为种子重夹逼
  （span 从 3 m/s 起按 2 倍扩张，新最优贴边则扩张重试）；
- 进入漂移模式后改用释放阈值 `slopeRelease`(0.0005)：慢漂结束后的残余
  滞后可能恰好停在进入阈值之下（锯齿相位问题，实测卡在 0.202–0.497
  m/s），漂移模式内持续精调直到斜率跌破释放阈值才退出——慢漂末段误差
  从 0.50 修到 0.00；
- 斜率正常 → 上下平移或无平移：argmin 未变，继续锁定。**判据只需要
  斜率，不需要参考功率**，因此 5% 的纯上/下平移零误触发（实测重搜次数
  恰为 0）。

检测下限 ≈ slopeThresh/P″（三次曲线 0.15 m/s、调试曲线 0.33 m/s）；更小
的纯 dx 平移稳态超额不足 0.01%，不追是合理取舍。

## 搜索能耗开关

```matlab
c = task1.config('energyAccounting',true);    % 开(默认)：寻优能量计入验收
c = task1.config('energyAccounting',false);   % 关：能耗列记NaN，只看定位与稳态
```

开关只作用于**评价与验收**（`task1.evaluate` / `run_task1_acceptance`），
不改变算法行为。"开"= 续航纪录口径（搜索阶段烧的电也算成绩）；"关"=
只关心最终找没找对。验收脚本两档都跑并分别列出。

## 验收结果（2026-09-01，MATLAB R2022b 实测）

- 单元测试 **16/16**；tracker 性能门槛 **8/8**（静态定位/入带≤25步/
  dx跳变恢复≤30步/dy零误触发/慢漂末段误差≤0.15/稳态≤0.2%/能耗开≤1.5%/
  关档全NaN）。
- tracker 关键实测（cubic）：静态 6 步入带；dx 跳变恢复 14 步（debug 10
  步）、误差 0.004 m/s；慢漂 5 次重搜跟踪、末段误差 0.001 m/s；稳态超额
  0.03%（含复探代价）；全程能耗 0.07–0.21%。
- 对照：ESC 恢复 56–68 步、全程能耗 0.54–0.64%；"搜索后锁定"基线跳变后
  停在旧最优（稳态超额 2.2–4.7%）；网格扫描全程能耗 16.9–19.7%。
- 完整逐场景数据由 `run_task1_acceptance` 重建于本模块 `results/task1/`（git忽略）；已核验摘要见 `docs/evidence/speed_shift_search/`。

## 诚实边界

- 代理曲线平移，非 X8 实测；任务 1 无噪声（噪声/多峰在任务 2）。
- 每评估步默认停留 `tEval=1 s` 的能耗归一化假设；能量口径是相对值
  （对离线最优功率的百分比），不是绝对瓦时。
- 平移时刻对搜索器不可见，但场景是确定性的；噪声下的阈值鲁棒性在
  任务 2 检验。
- 黄金分割/Brent 的最优性保证依赖单峰假设；多峰情形在任务 2 用
  多起点策略处理。
- "瞬时跳变速度"是任务设定，实机有速度动态与限速（+speedesc 工程已
  覆盖该情形）；两套工程的适用边界不同，不能混用结论。
