# 任务3.8：平台评价参照修复（滑动电压真下界）

> 本模块 = 3.7 全部成果 + 一项评价口径修复（2026-09-15）。入口 `open_3_8_demo.m`。

## 一、问题（为什么平台数字"好得不对劲"）

同一套算法接入平台 P2 数据源后，MOE/excess 反而优于本地代理——用户怀疑不对劲，
实验证实为**评价参照的系统性偏差**，与算法无关：

1. 平台的 `minPowerTrue` = 满电 OCV 稳态解析曲线的谷底**常数**；
2. 实时链 `plane.step` 的功率按**逐拍跌落的电池电压**插值台架分块系数——实测比该
   常数便宜 ~1.0%（3600s）～1.65%（9000s），随窗口单调加深；
3. 于是恒定参照在平台上不是真下界：26%～90% 的秒数功率"低于理论最低"，
   excess/MOE 被系统性美化。分解实测（3600s）：purerl_off 的 −0.50% =
   速度失配 +0.44% − 链条偏移 0.94%；9000s 的 −1.21% = +0.44% − 1.65%。
4. 次要真实因素：平台台架曲线谷底更平缓（偏 0.5/1/2 m/s 的惩罚 0.35%/1.36%/5.47%，
   本地为 1.72%/4.13%/4.64%），学习残差恰好落在平原区。

## 二、修复

`+w36/make_platform_plant.m`：
- 新增 `local_curveJV(pc,V)`：按指定端电压重算真值曲线（与 adapter truth() 同式）；
- 构造时在电压域建 41 点 `PminNormV` 查找表（满电 → 截止电压）；
- 逐秒日志 `minPowerTrue` 改为 `PminNormAtV(s.voltage_v)`——**随当前电压滑动的
  真值谷底**，恢复"该时刻可达的真空下界"语义；
- UI 真值曲线仍为满电口径（显示用）；本地后端零改动（其参照本就精确）。

## 三、验证

修复后同条件重跑（复合风 B=2.5 σ=0.3 seed=11）：

| 检查项 | 修复前 | 修复后 |
|---|---:|---:|
| 平台 openloop 3600s 违约秒占比 | 26.1% | **0.0%** |
| 平台 purerl_off 9000s 违约占比 / 链条偏移 | 90.2% / −1.65% | **≈0% / ≈0** |
| 平台 purerl_off 9000s excess | −1.21%（假象） | ≈ +0.4%（诚实） |
| 本地后端 | — | 零改动，回归全绿 |

各模型平台 MOE（3600s，用于 1-11 汇报第 25 页平台版图表）：见
`26isip_Aerospace/docs/evidence/platform_link/task38_eval_reference/moe38.csv`。

# 任务3.6：算法接入平台（P2 物理链后端 + 秒预算 + 平台就位判定）

> 第四轮（3.x）任务（2026-09-08）。**其余算法原样继承 3.5**（purerl_on/off/scratch +
> sweepcal / rl / hybrid / openloop / windinfer / est / known，含全部既有修复），
> 本任务只做一件事：**把算法的数据源从"本地代理对象"换成"平台 P2 物理链"**——
> UI 与算法逻辑不变，`plant.q/amendEstimate/count` 三原语后面接上平台。

## 一、三项拍板的落地（2026-09-08 与负责人确认）

| 拍板 | 落地 |
|---|---|
| 预算按【秒】丈量 | 平台后端 `count()`=任务窗内已消耗仿真秒数；算法 `n=c.evalSeconds`（默认 600s，UI 可调 100–3600s）；日志**逐秒一行** |
| 就位判定交给平台 | 指令变更后推进 `plane.step` 直到 \|v_meas−v_ref\|≤`settleTol`(0.1 m/s，对象侧判据)，再交付 1s 安静窗均值测量功率；暂态秒数计入预算与能耗（真实代价） |
| 评价用 MOE | `mop_moe` 直接吃平台逐秒日志表（Emin=逐秒理论最低功率列）；平台 Percent 口径留待 T2 正式横比时另接 |

## 二、平台后端（`+w36/make_platform_plant.m`）

- 底层：`models/plane/+plane` 的 `config/reset/step`（P2 冻结链：俯仰内核/台架合成/
  H3 诱导修正/H9 上限/电池链），内层 dt=0.01s，指令 ZOH 每 0.5s；
- 风世界线：复用场景湍流生成（composite 等七种），风真值只在对象侧；
- 测量链（T1 冻结语义）：算法可见功率 = 真值功率经 **0.2s 延迟 FIFO + 1.2% 噪声**；
  真值功率/最优速度/风真值只进评价列（红线1）；
- 功率归一：除以平台悬停功率（评价侧解析真值 J(0)≈487W），算法侧 hover≈1 口径不变；
- 平台真值：v*≈5 m/s、P(v*)≈360W（评价侧解析，与 harness 适配器同式）；
- 航向死推自洽：count()=秒 + tEval=1 → 算法 `sUsed`=实际耗时秒，ψ̂ 积分与对象相位一致。

## 四、结果（2026-09-08）

见 `results/report.md` 与 `results/platform_link.csv`。核心结果（2026-09-08，复合风 B=2.5+σ0.3、平台窗 900s）：
- sweepcal 盲找回平台真值谷底 û*=5.92（真值 5.15，误差 0.77），尾段超额 4.56%；
- known oracle 在复合风平台场景超额 7.58%（高于开环 5.71%）——**平台慢俯仰内核(t63≈2.84s)下追风补偿的暂态代价>收益**，是平台集成揭示的第一条物理性结论；零风场景 oracle 超额<3%（信息上界口径）；
- purerl_off 预训练离线部署 优于平台开环（门槛通过）；
- 本地后端回归：3.5 全部门槛与单元测试原样保留并通过。核心门槛：
- 平台对接：逐秒日志覆盖任务窗（预算按秒）；sweepcal **盲找回平台真值谷底**
  v*≈5（误差<1.2——平台真值是算法从没见过的"新曲线"，无位置先验验证）；
  known oracle 超额<3%（MOE 上界）；purerl_off 优于平台开环（预训练离线部署）；
- 本地后端回归：3.5 全部门槛与单元测试原样保留并通过（"其余算法不变"的证明）。

## 五、边界与红线

- 平台后端固定 static 场景（曲线恒定）；跳变类场景后续扩展（平台真值无平移机制）；
- 预训练（purerl_on/off）的试飞时段同样在平台物理链上进行（独立实例、不同湍流实现），
  `plWarmMax` 语义=预训练**调用数**上限（另有 60× 秒数安全上限）；
- 红线1/2/3 全部适用：因果白名单不变、对象接口三原语不变、proxy 等级不外推。
