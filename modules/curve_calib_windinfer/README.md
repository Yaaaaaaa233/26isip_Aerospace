# 任务3.3：标定后在线策略消融——"首飞标定 + task2式在线"可行吗？

> 第三轮（3.x）第三个任务。对象物理与 3.1/3.2 完全一致（曲线未知、风未知、空速=地速−风、
> 转圈、时延、限幅）。**来源（用户问题，2026-09-07）**：在 task3 场景下，先通过首飞全飞
> 拟合速度-功率曲线，之后用 task2 的算法（风推断）还是 task3 的强化学习效果更好？
> 本任务把用户设想（首飞标定 + task2 式在线）实现为 `hybrid` 策略，与 sweepcal（task3 机器）、
> rl（RL 对照）在同一矩阵里做**受控消融**，给出有证据的答案。编号见 [../ROADMAP.md](../ROADMAP.md)；
> 全版本脉络见 [../模型与算法梳理.md](../模型与算法梳理.md)。

## 一、答案（先说结论）

| 场景 | 标定后用什么在线 | 证据（800步、2种子均值，见 checks 报告） |
|---|---|---|
| **恒定风 / 无风** | **task2 式在线可行且更简单**（hybrid：冻结曲线+风修正+信赖域探针），代价 ≈0.2pp；零风下反而优于 sweepcal | hybrid 2.10%（零风 2.49%）vs sweepcal 1.91%（零风 2.69%） |
| **变风** | **必须继续 task3 式在线**（sweepcal 机器或 RL）；冻结曲线在线**不成立**（劣于开环） | hybrid 12.51%（û*误差7.2 m/s）vs sweepcal 5.10% vs openloop 4.80%；RL 3.52% 为变风最优 |

机理（调参实验定位，见第三节）：
1. **变风污染首飞标定**：composite 风的慢变周期（≈78 s）与 150 步标定窗相当，标定期
   风在漂 → 联合拟合的 argmin 本身就落在 12–15 m/s（真值 6.3）；
2. **冻结曲线后 û* 没有再锚定**：sweepcal 的 uHat 轨迹同样会甩到 14.5，但它每 20 步
   重拟合的 argmin 持续把 û* 拉回真值邻域；冻结后探针链被风调制偏置拖着走，信赖域
   （±1.5 m/s）也救不了——因为信赖域中心（标定 argmin）本身就是错的。

## 二、hybrid 策略（`+w33/hybrid_run.m`，用户设想的最忠实实现，纯因果）

**Phase A 首飞标定（150 步，与 sweepcal 完全一致）**：速度双向斜坡扫 3→12→3 m/s，
联合辨识 `min_{f,w} Σ (Pᵢ − f(|vᵢ·t̂ᵢ − w|))²`（归一化基四次多项式）；û*=argmin 限制在
样本覆盖范围（禁止外推）。

**Phase B 在线（相对 sweepcal 的三点改动）**：
1. **风修正更细**：每 10 步（sweepcal 每 20 步）做 `wind_corr` 增量风修正
   （3 参数 δw+c0——2.1"功率调制反推风"的增量形式，c0 吸收 f̂ 形状偏差）；
2. **曲线维护更稀**：每 60 步（sweepcal 每 20 步）才冻结 w 线性重解 f，且须过双向接受
   （联合集 SSE 改善 >0.2% 且 标定块 SSE 不退化 >0.5%）；
3. **探针锚加标定信赖域**：û* 限制在标定 argmin ±1.5 m/s（本对象族曲线物理固定，
   û* 漂移只能是估计失败）。

## 三、调参史（负结果全记录，2026-09-07）

按时间序，每个变体都在 恒定风3.5@40° / 变风composite / 零风（seed 3, 600–800 步）单点验证：

| # | 变体 | 恒定风 | 变风 | 结论 |
|---|---|---|---|---|
| v1 | 冻结 f̂ + 每步纯二维滑窗反演（无 c0） | û*、ŵ 全崩 | — | **形状-风简并**：f̂ 的形状偏差被 w 补偿，风估计漂到 >9 m/s（3.1 注释早有预警） |
| v2 | 冻结 f̂ + 每步三维反演（δw+c0）+ 窗长自适应 | 300步 wErr 0.64（可用） | 800步 wErr 9.9 | c0 必须有；但守卫重拟合（联合集 SSE 改善即接受）被"近窗聚类过拟合"骗过，弯曲线把 û* 拖向边界 |
| v3 | 增量 wind_corr + 低频守卫 | 2.73%（尾2.33） | 9.27% | 零风下 δw 在守卫间隔随机游走（wErr~1）；变风下守卫接受弯曲线 |
| v4 | v3 + 守卫采纳联合拟合的 w | 尚可 | **û* 漂到 12.9，9.67%** | 变风下联合拟合的 w = "标定风+旧风"混合偏置，每次采纳都拽回追踪 |
| v5 | 每步三维反演 + 信赖域 + 稀疏守卫 | — | û* 仍滑 | 反演的简并随机游走是元凶，弃用 |
| v6 | **wind_corr(每10步) + 探针锚 + 曲线维护(每60步) + 信赖域（最终版 hybrid）** | **2.35%（尾1.89）** | **11–14%（负结果）** | 恒定风成立；变风失效根源=标定本身被污染+û*无再锚定（信赖域中心即错） |
| 对照 | sweepcal（重拟合20+探针15+wind_corr20） | 1.91% | ~5%（uHat 甩到 14.5 再被拉回） | 高频重拟合 argmin 是变风下的**承重锚**，频率不能降 |
| 对照 | sweepcal 但 wind_corr 提到每10步 | 3.49%（更差） | 5.47% | 连"细化风修正"都破坏平衡——sweepcal 的节奏是整定过的 |

## 五、边界与红线

- hybrid/sweepcal/rl 经 `ctrl_view` 白名单运行，无曲线/u*/风/噪声真值（红线1，测试核验）；
- "曲线物理固定"是本对象族设定，信赖域合法性依赖于此；真实平台曲线慢漂时恒定风
  下的简化优势会缩小（需恢复低频维护）；
- 变风负结果的边界：composite（慢变+湍流）口径、风漂移周期与标定窗相当时成立；
- 全部结论为 proxy 等级（红线3），不支持真实 X8 节能表述。
