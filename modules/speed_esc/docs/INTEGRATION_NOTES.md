# 整合说明：不是把配比改名为速度

## 1. 先分清三种量

原 `ratio_esc` 的变量是上、下旋翼转速比 `eta = Omega_u/Omega_l`，不是直接的电功率分配百分比，也不是推力比。本工程的变量是平飞速度，单位为 m/s。

两个问题能共用“改变参考、观察功率、估计方向、继续调整”的优化结构，但不能共用未经换算的曲率、学习增益、执行限制或物理约束。

| 差别 | 原转速比问题 | 本轮平飞速度问题 |
|---|---|---|
| 输出参考 | 无量纲转速比 | 速度参考，m/s |
| 稳定层需要保证 | 总推力、偏航力矩和电机约束 | 速度跟踪、高度、航向和任务约束 |
| 功率对象 | 恒推力假设下的配比曲线 | 固定配比假设下的速度曲线 |
| 动态代理 | 配比执行响应 | 已有速度闭环的总体响应 |
| 真实数据 | 上下桨转速/推力及电功率 | 实际速度、风、姿态及同步电功率 |

本版假设上下桨配比固定为1，但没有实施共轴控制分配。这只是缩小研究变量，不等于已经满足实机总推力或偏航约束。

当前目标是给定代理工况下的平均功率最低。它不是单位航程能耗 `P/v` 最低，也不能把非零最优速度用于必须定点悬停的任务。

## 2. 从同学Python中保留什么

源文件是相邻 `速度寻优代码` 中的 `esc_core.py`、`v1_static.py`、`v2_dynamics.py`、`v3_robust.py`、`demo_kit.py` 和 `README.md`。

保留了两类速度功率曲线、静态到动态再到带噪延迟的分阶段路线，以及基于实际速度的窗口回归。新工程不需要Python运行环境。

```text
V1：参考速度立即成为实际速度 -> 功率
V2：参考速度 -> 一阶速度闭环代理 -> 实际速度 -> 功率
V3：V2 + 功率测量噪声 + 传输延迟 + 未知最优点变化
```

三种模式都可以单独运行：固定参考只检验执行响应；仅微扰只检验局部响应；完整ESC才更新参考中心。不要把V2中的一阶模型再理解成“我们重新设计了一套飞控PID”。

## 3. 两种梯度估计怎样互补

### 默认：窗口回归

在最近一段时间里，用同一采样时刻的速度 `v_i` 和功率 `J_i` 估计局部斜率：

```text
g_raw = sum((v_i-mean(v))*(J_i-mean(J))) / sum((v_i-mean(v))^2)
```

然后低通滤波，按负梯度调整参考中心。微扰使实际速度持续变化，避免回归分母接近零。若窗口未填满或速度变化不足，就不更新中心。

优点是直接利用实际速度，不必假设参考指令已经准确执行。局限是窗口内的风、功率偏置或对象变化会混入回归结果；它并不天然免疫延迟、噪声或动态滞后，也不保证得到真实解析梯度。

### 对照：经典同频解调

继承原MATLAB工程的高通、正弦解调、低通链：

```text
功率 -> 高通去除慢变基线 -> 乘以 (2/a)*sin(omega*t_sample)
     -> 低通梯度估计 -> 负梯度积分
```

解调使用功率的采样时间，而不是收到数据的时间，因此补偿了已知测量时间偏移；但执行响应仍会造成相位滞后。不能据此声称所有延迟都已消除。

回归模式下，高通输出仅记录为诊断信号，不进入回归。两种方法采用不同的默认增益和滤波参数，少量对照不支持“某方法普遍优于另一方法”的结论。

## 4. 本次实际修正的逻辑

1. **先算对象，再生成下一条参考。** 第k步应用上一条指令，收到本步数据后才输出下一条指令，没有预先访问未来反馈。
2. **速度和功率必须配对。** 原Python V3将延迟后的功率与当前速度回归；本版将功率、对应速度、采样时间一起经过FIFO。启动阶段重复的旧采样不会被当作新样本重复计数。
3. **精确一阶离散与硬限速分开。** V2/V3使用 `v_next = exp(-Ts/tau)*v + (1-exp(-Ts/tau))*v_ref`。一阶响应不等于硬加速度约束，所以参考端另有显式变化率限制。
4. **中心和参考分开限幅。** 中心限制在 `[lower+a, upper-a]`，给微扰留空间；发出的参考再执行幅值和变化率限制。代理模型没有把这些仿真值认证成实机安全值。
5. **完整窗口预热。** 两种估计器均先建立有效窗口；无效、过期、时间倒退的数据触发冻结和估计器重建。显式冻结停止参考更新，恢复后重新预热。
6. **用实际速度和对象真值评价。** 微扰和执行响应造成的功率代价保留在验收中，不用带噪测量功率计算节能率，不只看参考中心是否接近答案。
7. **统一时间单位。** 角频率0.5 rad/s约为0.0796 Hz；报告使用秒，而不是把采样步数当秒。

界面的“暂停”只暂停播放，不是上述控制器冻结。两者用途不同。

## 5. 为什么默认回归窗口改成126点

同学原实现的63点约为半个微扰周期。本版先在种子1至5、V3动态变化场景中比较了63、126和252点，以下是当时记录的末段速度误差：

| 曲线 | 窗口点数 | 五次平均误差 m/s | 五次最大误差 m/s |
|---|---:|---:|---:|
| 二次调试 | 63 | 0.960 | 1.510 |
| 二次调试 | 126 | 0.463 | 0.778 |
| 二次调试 | 252 | 2.389 | 2.696 |
| 三次代理 | 63 | 0.866 | 1.636 |
| 三次代理 | 126 | 0.268 | 0.580 |
| 三次代理 | 252 | 1.307 | 1.455 |

这些是选择默认参数的探索数据，不是最终验收。完整周期改善了这组噪声条件下的估计；两周期窗口又因滞后影响追踪。正式随机场景改用未参与窗口选择的种子11至20，仍保留速度指标未达标项，详见 [验证记录](VERIFICATION.md)。

## 6. 如何确认移植没有误读原代码

`+speedesc/python_reference.m` 是隔离的兼容复现器，特意保留原Python的更新顺序、欧拉离散、半周期窗口、旧延迟配对和原限制逻辑。它不作为新版推荐控制器。

`tests/fixtures` 是直接执行原Python后导出的14组逐样本数据；`provenance.json` 记录源文件SHA256。`verify_python_parity` 对照复现器的6个信号，最大误差约 `5.33e-15`。

这一步只证明“准确理解并移植了同学的方法”。新版控制器修改了时间配对、限制和窗口，所以不应要求它仍与原Python逐点相同。新版另与Simulink进行同输入的一致性测试。

## 7. 刻意没有照搬的结论

- 三次代理曲线不是完整气动方程，也不能证明共轴X8的真实最优速度为6.3 m/s。
- 改变 `v_star` 会改变代理曲线；三次形式属于横向缩放，不能直接等同于电量下降、风速变化或简单平移。
- 局部窗口回归不是一般意义上与经典ESC严格等价的估计器。
- 本实验没有证明信息论最优性、全局最优或飞行稳定性。
- 平坦曲线上的功率误差很小，不代表最优速度已经被精确识别。

下一步应先用真实或更高保真数据检验速度-功率关系，再根据真实响应、噪声和延迟重新调参，而不是直接把当前参考输出接到飞机上。
