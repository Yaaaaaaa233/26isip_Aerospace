# 真实数据与强化学习：本版接口边界

## 1. 现在可以做什么

本版提供两条独立入口：`replay_speed_log` 将已有飞行日志用于时间对齐和影子建议检查；`speedesc.make_rl_env` 在与ESC相同的虚拟速度对象上验证RL接口。前者不下发任何指令，后者不宣称已经训练出智能策略。

```matlab
L = replay_speed_log('D:/logs/flight01_si.csv',500);
env = speedesc.make_rl_env;
validateEnvironment(env);
observation = reset(env);
[observation,reward,done] = step(env,8);
```

这里500是示例归一化尺度，单位W；8是速度动作，单位m/s。

## 2. 日志字段与时间配对

数据模板在 `data/telemetry_template.csv`：

| 字段 | 含义 | 单位 |
|---|---|---|
| time_s | 本行数据在接收端可用的时刻 | s |
| velocity_time_s | 水平速度原始采样时刻 | s |
| vn_mps、ve_mps | 北向、东向实际速度 | m/s |
| battery_time_s | 电压电流对应的功率采样时刻 | s |
| voltage_v、current_a | 对齐后的电压和放电电流 | V、A |

所有时间必须使用同一时钟原点，`time_s` 严格递增，信号时间不应倒退或来自未来。输入端需要先处理各设备时钟差、单位和电压电流自身的采样对齐。本函数不解析原始ULog/MAVLink二进制，也不建立UDP连接。

每个控制采样点只使用此刻已收到的日志行。针对功率采样时刻，寻找已收到且不晚于该时刻的最近速度样本；间隔大于一个 `Ts` 就判为不可配对，而不是用未来速度插值。超过 `maxAge`、缺测或无效数据会停止更新。

```text
收到时刻12.5 s
功率采样12.0 s -> 使用12.0 s附近、但不晚于12.0 s的速度
不要直接把12.5 s的当前速度配给这份功率
```

归一化为 `J = voltage_v * current_a / powerReferenceW`。尺度应来自事先确定的标定值，不能依赖整段未来日志的最大值。真实功率单位是W，而本版代理模型的J没有被标定成真实W。

当前速度由 `hypot(vn_mps,ve_mps)` 得到，是地速。存在风时，地速不等于空速；建议保留水平风矢量，并区分任务地速目标和气动空速变量，不能只把一个“风速大小”随便加进曲线。

## 3. 为什么回放不等于闭环验证

输出列名故意使用 `candidate_speed_NOT_APPLIED`。这些建议没有改变记录中的飞机速度，因此后续记录的功率也不是这些建议造成的。

回放可以检验单位、时间戳、缺测处理和控制器是否产生合理建议；不能据此计算执行该策略之后的真实节能率。同理，不能拿历史日志的下一条功率当作任意RL动作的真实后果。

有数据后，建议分三步推进：

1. 先对速度、电功率、高度、姿态、风和电池状态做同步与质量检查，筛选近稳态平飞片段。
2. 用训练数据辨识功率代理和速度响应，保留不同日期/工况数据用于独立检验；合理约束外推范围。
3. 用辨识对象运行ESC/RL对照，通过SITL或受控联调验证指令生效、稳定层和超时回退，之后才讨论飞行实验。

## 4. 新速度RL接口

动作是 `[0,20]` m/s内的速度参考，每1 s更新；内部仍以0.1 s推进。同一时刻只能由ESC或RL中的一个生成速度参考。

每帧观测包含6个量，叠加最近4帧成为24维向量：

- 归一化实际速度；
- 归一化参考速度；
- 本动作窗口的平均测量功率；
- 与上一动作窗口相比的功率变化；
- 功率测量年龄；
- 有效测量覆盖比例。

观测不含真实最优点、整条曲线、解析梯度或未来工况通知。环境内部的 `LoggedSignals` 保存仿真状态，但不是策略输入。

奖励是负的窗口平均测量功率，加上缺测/冻结惩罚及小幅参考变化惩罚。测量延迟意味着当前窗口可能包含上一动作的影响；有限历史有帮助，但不保证构成完全可观测的马尔可夫状态。

当前测试覆盖环境验证、确定性重置、动作边界及完整回合，未训练本版TD3。固定动作下对象序列与ESC工程的固定参考模式一致；这是接口与对象一致性的检查，不是RL策略成绩。

## 5. 风速、电量等因素怎么延续

`make_context_speed_env` 可选复用相邻 `energy_data_rl` 中已有的风/SOC工况环境，并把优化模式设成速度。保留原工作，不把两个工程里不同的代理模型静默混为同一个模型。

```matlab
contextEnv = make_context_speed_env;
validateEnvironment(contextEnv);
```

这个环境与本版的功率模型和观测不相同，不能直接比较原始reward或节能百分比。正式对照应让ESC与RL使用同一个对象、相同初始条件、相同噪声序列、相同边界和相同评价指标。

后续若扩展本版观测，建议优先加入可实际获得并有质量标记的风矢量、SOC、电压、载荷和稳定层状态。SOC和电压有相关性，但不是同一个量；电压变化也不必然导致功率最优速度变化，需要测量或模型支持。跨风/SOC训练与测试场景应分离。

## 6. 和同组同学的接口

功率/动力学同学负责对象：输入速度参考和工况，输出带采样时间的实际速度、电压电流以及状态质量；算法同学只通过反馈生成速度参考，不读取对象私有最优点；数据/测试同学负责同步、场景、固定基线和独立评分。

最终接飞控时，保留已有速度与姿态稳定层。慢层只给出经过任务边界、限速和安全检查后的速度参考；高度、航向、飞行模式、超时/掉线与人工接管必须由明确的控制逻辑负责。本工程没有实现这些实机约束，也没有实现上下桨分配。

原 `ratio_esc` 可继续作为另一个独立研究分支。以后要耦合时必须先建立速度与配比同时变化的功率对象和稳定性约束，不能把两条相互独立的一维虚拟曲线拼起来当作已验证的二维物理模型。
