# 平飞速度ESC：MATLAB整合版

本工程整合了同学 `速度寻优代码` 的Python方案与本仓库 `modules/ratio_esc` MATLAB工程。**本轮只优化平飞速度，假设上下桨配比固定为1；对象仍为虚拟功率曲线，不是X8实测或完整飞行动力学。**

原Python文件、转速比工程和数据/RL工程均保留，不改动已有成果。本目录运行不需要Python；`tests/fixtures` 是事先由原Python程序生成的验证数据。

**在本仓库中的定位**：速度单变量慢层优化器的算法线验证模块（虚拟功率代理上的完整验收）。接入 PX4 X8 平台（M0-C 及之后）时，以 `docs/interfaces/M0A_OBSERVABILITY.md`、`docs/interfaces/M0B_SPEED_LOOP.md` 与 `docs/interfaces/M0C_SPEED_ESC.md` 固定的接口为准；当前 M0-C 方案选用 `modules/ratio_esc/+ratioesc` 内核做速度语义映射，本模块的回归估计器、窗口选择与验收结论可作为参数整定和后续内核替换的依据。**算法不得直接驱动 8 路 PWM。**

## 1. 先运行哪个文件

MATLAB R2022b中打开并运行 `START_HERE.m`，会打开中文面板。初次建议按这个顺序看：

1. 选择 **V1静态、完整ESC**：速度指令立刻生效，先观察能否根据反馈找到低功率区域。
2. 选择 **V2速度响应**：实际速度逐渐跟上指令，功率由实际速度计算。
3. 选择 **V3噪声/延迟/变化**：默认相对2%噪声、0.5秒延迟，60秒时隐藏最优速度改为9 m/s。
4. 用 **仅微扰** 看中心不动时反馈怎样变化；用 **固定参考** 看不寻优的速度响应。固定参考模式可分别设置初速与固定参考值。

面板默认窗口回归算法，另可切换经典同频解调作为对照。参数在重置或下一次播放时生效；曲线/估计器切换会载入对应默认学习增益。播放只是已完成因果仿真的逐帧展示，不改变控制器计算。

```matlab
launch_speed_esc              % 中文面板
run_speed_demo                % 两类曲线、三个版本与解调对照，导出图表/动画
run_speed_acceptance          % 单元、Python复现、Simulink一致性与性能报告
qa_speed_ui                   % 面板回调与桌面/紧凑窗口截图

[file,model] = build_speed_simulink;
open_system(file);            % 可打开、运行的Simulink闭环
```

只有数据处理和纯MATLAB仿真时不需Simulink。Simulink构建需要Simulink/Stateflow；完整验收中的RL检查需要Reinforcement Learning Toolbox。缺依赖会记录错误，不会假装通过。

## 2. 四张图分别看什么

| 图 | 观察内容 |
|---|---|
| 左上：功率曲线与反馈 | 横坐标是与功率同一采样时刻的实际速度，曲线和最优点仅给评价器看 |
| 右上：参考与响应 | 参考中心、包含微扰的执行指令、实际速度；这三者不是同一个量 |
| 左下：功率 | 接收到的延迟带噪测量，与仅评价用的当前对象真值/最优基准 |
| 右下：梯度估计 | 原始回归斜率或解调输出，与低通后的梯度；正值减速，负值加速 |

显示/隐藏评价器曲线不改变仿真日志。高通输出另存在CSV的 `highpass` 列；回归模式下它只作诊断，不参与回归梯度，不能把它解释成回归算法的输入。

## 3. 相互取长补短后的选择

| 内容 | 同学Python | 原MATLAB转速比 | 本版处理 |
|---|---|---|---|
| 优化变量 | 平飞速度 | 上/下桨转速比 | 只输出速度参考，配比固定 |
| 对象阶段 | 静态、一阶、抗扰 | 静态/反馈/微扰/闭环 | 保留V1–V3，并保留固定/微扰观察模式 |
| 梯度估计 | 功率对速度的窗口回归 | 高通、同频解调、低通 | 两种方法可切换，默认回归，不声称普遍等价 |
| 延迟反馈 | 延迟功率配当前速度 | 功率延迟链 | 功率、对应实际速度、采样时间一起排队 |
| 参考保护 | 中心限幅，执行对象再裁剪 | 参考投影、限速、冻结 | 中心留微扰余量，参考独立限速，异常冻结并重新预热 |
| 梯度启动 | 部分模式预热 | 状态重置/恢复 | 所有模式完整窗口预热，并检查速度激励强度 |
| 功率模型 | 二次调试与三次代理 | 配比二次代理 | 保留两类速度曲线，不拿配比曲率直接换单位 |
| 验收 | 多处以步数与中心值判断 | 独立真值功率评价 | 统一秒、实际速度与无噪声对象功率；同时报告速度误差 |

## 4. 两类曲线及默认参数

```text
调试曲线：J(v) = 1 + 0.003 * (v-v_star)^2，初始v_star=6 m/s
三次代理：J(v) = 1 - 0.261*x^2 + 0.174*x^3，x=v/v_star
           初始v_star=6.3 m/s，最低J=0.913
```

三次曲线是同学代码的经验形状代理，不是Hwang/Opazo论文原方程的严谨复现。改变 `v_star` 是横向缩放，不是严格的曲线平移；工况跳变只用于检验未知对象变化，不能直接解释成电池电量下降。

默认：采样0.1 s，总时长120 s，速度范围0–20 m/s，微扰幅值0.5 m/s，角频率0.5 rad/s（约0.0796 Hz，周期约12.57 s），一阶时间常数2 s。**rad/s不是Hz。**

回归窗口默认126点，约一个周期；同学原代码是63点半周期。前期种子1–5对照支持使用完整周期以减轻噪声，过长窗口又会增加跟踪滞后。正式性能报告使用未参与该选择的种子11–20，不保证其他工况同样通过。

回归默认增益：二次22、三次8，低通角频率2 rad/s；解调对照默认增益：二次8、三次2，低通0.05 rad/s。两者不是同一滤波器，参数不能机械照搬。参考中心变化不超过0.8 m/s每秒，实际参考变化不超过1 m/s每秒；这些都不是实机安全值。

## 5. 在线性与逐步顺序

每个采样时刻：上一条参考推动对象 -> 按实际速度生成当前功率 -> 测量链给出到达数据及其采样时刻 -> 估计梯度 -> 生成下一条参考。

```matlab
c = speedesc.config('version',3,'curve','cubic','method','regression');
p = speedesc.controller_config(c); % 白名单，不含功率曲线、最优点或跳变时刻
s = speedesc.esc_reset(10,p);
[nextReference,s,diagnostic] = speedesc.esc_step( ...
    s,0.98,7.2,12.0,12.5,true,p); % J、配对速度、采样时刻、当前时刻、有效标志
```

控制器没有接收 `v_star`、整条曲线或解析梯度。注意示例12.5秒收到的功率对应12.0秒，所以速度也应是12.0秒的速度，不是12.5秒的新速度。

## 6. Simulink模型

`models/speed_esc_closed_loop.slx` 展示参考记忆、速度响应、功率代理、测量配对、梯度估计、参考更新与日志。估计器与参考更新块调用和MATLAB同一套核函数；不是把完整闭环塞进一个黑箱。速度响应和延迟链展开为原生离散模块。

模型保存本次配置和确定性输入，初始化时自动加入本工程路径。使用相同预生成噪声验证V1/V2/V3、两种估计器，并覆盖无效数据及冻结恢复。构建函数会重建本工程的SLX，手动修改模型前应另存工作副本。


可选工况桥接依赖仓库外的相邻工程 `energy_data_rl`（不在本仓库内，需自行放在同级目录），其风/SOC模型与本版功率曲线不同，不能直接横比reward或节能率。真实数据与RL的进一步边界见 [数据和RL说明](docs/DATA_AND_RL.md)。

## 8. 输出与限制

本机实际结果：14项单元测试、14组Python复现、6组MATLAB/Simulink一致性检查通过。推荐回归算法功率指标74/74达标，速度定位指标63/74达标。未达标项与评价口径见 [验证记录](docs/VERIFICATION.md)，没有将部分性能通过写成全部通过。

- `results/v1_*、v2_*、v3_*`：PNG、FIG、CSV、MAT；V3三次曲线另有GIF。`results/` 由上述脚本在本地重建，不进入版本库。
- `results/acceptance/report.md`：实际验收结果；0表示未达标，不会把边缘项改写为通过。
- `results/python_parity.csv`：原Python逐样本复现检查；它验证移植，不能替代改进版性能验收。
- 仓库内精选证据（验收报告与汇总CSV、各场景总览图、V3过程动画、Simulink结构图）见仓库 `docs/evidence/speed_esc/`。
- 仍没有六自由度飞行验证、真实功率标定、姿态/高度/偏航约束、实机飞控指令发送或SITL联调。

**当前优化目标是平均功率最低，而不是最小P/v的最远航程，也不是必须定点悬停的任务。**实际工程中的平飞还需约束高度、航向和任务进度。新速度模块与原转速比模块在这些物理约束上不同，不能因为都用虚拟数据就视为同一物理问题。
