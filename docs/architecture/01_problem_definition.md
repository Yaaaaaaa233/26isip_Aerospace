## 先看结论

- 我们建议把最终项目说成：**无人机绕圈等待时，根据风和实时功率自动调整速度，尽量省电，同时不能飞出轨迹或触发安全限制。**
- 现在先把直线、无风、只调速度做扎实；之后再加圆周、风、上下桨转速比。
- RL 已有接口、TD3/BC 训练和对拍预研，但暂不接入正式平台。因为任务、统一 Plane 功率对象和评价闭环还没有完全定下来。

## 1. 这份文档解决什么

这份文档用来统一全组对项目的理解：我们到底要解决什么、能调什么、不能违反什么、怎样才算成功。以后如果目标变了，先改这里，再改代码，避免五个人做出五种不同的问题。

## 2. 建议的最终任务

建议将最终任务表述为：

> 面向共轴八旋翼在固定高度巡航或盘旋等待任务中的续航需求，在风场、测量和对象参数变化的情况下，根据实时飞行状态与电功率反馈，在线生成前飞速度参考值，并在后续扩展上下旋翼转速比参考值，使飞行器在满足轨迹、姿态和执行器约束的前提下降低平均电功率、提高估算续航时间。

推荐把**固定高度圆周盘旋等待**作为最终展示场景，把直线平飞作为开发和验证基线。圆周场景具有重复、封闭、易比较和易可视化的特点，也能让固定世界坐标系风在机体沿程方向上产生周期变化。

该任务选择仍须由指导教师确认。确认项见 [`ADR-001-objective-selection.md`](../decisions/ADR-001-objective-selection.md)。

## 3. 我们到底在优化什么

### 3.1 当前建议：让无人机留空更久

在固定任务时域 `T` 内最小化平均电功率：

```text
min_pi J = (1/T) * integral_0^T P_e(t) dt
P_e(t) = U(t) * I(t)
```

这里的 `pi` 只是“决定参考速度的算法”，可以是固定值、ESC，未来也可以是RL。若可用电池能量为 `E_usable`，续航可粗略估算为：

```text
T_endurance ~= E_usable / mean(P_e)
```

在纯仿真阶段，`P_e` 必须标注为 `estimated`；只有完成数据来源说明和校准后才可标注为 `measured` 或 `calibrated`。

### 3.2 暂不作为主目标的口径

- 固定航程任务应最小化总能量 `integral(P_e dt)`。
- 最大航程任务应关注单位距离能耗，稳态近似为 `P_e / v_ground`。
- 本阶段不把平均功率、总能量和 `P/v` 混成一个无权重依据的“多目标函数”。任务口径改变时必须新建或修订 ADR。

## 4. 决策变量与分层控制

当前阶段的慢层决策变量为：

```text
v_ref(t)                         前飞/沿轨迹速度参考值
```

M2 及后续阶段扩展为：

```text
v_ref(t)                         速度参考值
eta_ref(t) = omega_upper / omega_lower
```

慢层可由固定基线、解析策略、ESC或未来RL实现。慢层不得直接输出八路PWM。姿态、角速度、轨迹跟踪、速度闭环和X8控制分配属于快层控制责任。

## 5. 约束

最终优化至少受以下约束：

| 类别 | 约束示例 | 当前实现状态 |
|---|---|---|
| 速度 | `v_min <= v_tangent <= v_max`，参考变化率受限 | 平台已有速度参考范围和变化率保护 |
| 高度 | `abs(h-h_ref) <= e_h_max` | 需形成统一评价口径 |
| 轨迹 | 圆周场景 `abs(r-R) <= e_r_max` | 代理RL环境已有径向误差，平台尚未统一 |
| 姿态/偏航 | 姿态、角速度和偏航误差有界 | 平台已有部分监视与故障回退 |
| 执行器 | 八电机转速/PWM不饱和 | 已观测；M2受约束 eta 分配器已放行 |
| 转速比 | `eta_min <= eta_ref <= eta_max` 且总推力/力矩可实现 | `ratio_esc`代理有限幅，平台M2已完成受约束分配与验收 |
| 数据 | 功率、速度等失效时冻结优化并回退 | 平台M0-B/M1已有保护基础 |

验收阈值应由场景配置给出，不在算法内硬编码为无法追溯的常数。

## 6. 什么叫“在线”

“在线优化”表示策略在运行过程中只使用当前和历史可测信息更新决策：

```text
available: time, measured state, measured/estimated power,
           data validity, past commands, optional measured wind
forbidden: complete future wind, full hidden power map,
           true optimum, analytical gradient of the hidden plant
```

离线扫描、解析最优值和完整功率曲线可用于生成评价基准，但不得进入在线控制器或RL观测。

## 7. 一步一步把问题做复杂

| 问题 | 场景 | 决策变量 | 目的 |
|---|---|---|---|
| L0 | 静态代理对象 | `v_ref`或`eta_ref` | 检查算法方向、边界和因果性 |
| L1 | 无风直线平飞 | `v_ref` | 建立速度在线寻优基线 |
| L2 | 有风直线/圆周 | `v_ref` | 区分地速、空速和沿程风影响 |
| L3 | 固定典型速度或悬停 | `eta_ref` | 接入X8上下桨受约束分配 |
| L4 | 圆周不规则风 | `v_ref`，必要时残差修正 | 比较解析、ESC与未来RL |
| L5 | 已校准对象 | `v_ref`与`eta_ref` | 交替或协同优化 |

这里使用 `L0--L5` 表示问题复杂度，避免与执行路线中的 Plane 工作包 `P0--P4` 混淆。L0/L1已有代理对象证据；L2/L4已有独立风场和RL预研证据但尚未进入统一闭环；L3已完成平台M2；L5尚未开始。

## 8. 系统边界

### 8.1 系统内

- 风场与任务场景生成；
- X8动力学、推进、电池和功率对象；
- 快层飞控、控制分配、安全回退；
- 慢层在线优化；
- Harness、日志、MoP/MoE计算与可视化。

### 8.2 外部参与者

- 操作者/指导教师：选择任务和场景、设置约束、审查结果；
- PX4/QGC或日志源：提供状态与电源数据、接收高层参考；
- 台架/CFD/BEMT/文献：提供对象校准依据。

### 8.3 本阶段明确不做

- 不让慢层算法直接驱动PWM；
- 不把代理功率曲线结果称为真实节能率；
- 不把代理环境中的TD3/BC训练结果称为不规则风优化已解决；
- 不在真实安全边界未知时进行自主实飞验证；
- 不同时求解航程、续航、载荷和所有故障问题。

## 9. 成功判据

项目最终成功不等同于“某次曲线下降”。至少应满足：

1. Wind、Plane、Control和Evaluation接口可独立替换并一键运行。
2. 固定基线、解析/ESC策略和候选学习策略使用相同场景、种子与评价窗口比较。
3. 优化策略降低选定任务口径下的功率或能量指标，同时零硬约束违规。
4. 结果可追溯到场景配置、代码版本、模型/数据来源和指标公式。
5. 对代理、校准仿真、SITL/回放和实测结果使用不同证据等级。

具体需求、指标和验证场景见 [`05_verification_traceability.md`](05_verification_traceability.md)。

## 10. 当前已知缺口

- 当前PX4-X8平台的 `P_est` 未校准且工作点附近功率面平坦，M1结果只能证明闭环和保护机制未变坏。
- 当前平台“风扰动”尚未与世界坐标系风矢量、空速/地速和圆周运动统一接入；`wind_field_sched` 只提供可复用的独立代理实现。
- M2的上下桨配对、旋向和受约束控制分配器已完成五轮复验；下一步是 M3 交替协同和 Plane 接入后的回归。
- Harness 的代理 MOP/MOE 指标层已实现，但尚未把 Wind、Plane、Control 接入同一闭环。
- TD3/BC 已有训练与未见种子评估；从零 TD3 和隐藏风场表现仍不足，且尚未接入统一 Plane/PX4 平台。

这些缺口决定了近期优先级应是问题口径、物理对象、场景、接口和Harness，而不是扩大RL训练规模。
