## 0. 2026-09-03修正版研究路线

### 0.1 先统一研究对象

无风仿真扫描得到的 `P_nom(v_air,eta)` 是名义模型，不是在线算法要重新“发现”的唯一答案。在线策略面对的运行对象允许相对名义模型存在风、转弯、执行动态、电池和参数偏差：

```text
P_hidden = F(v_air, eta, turn, battery, disturbance; hidden_parameters)
P_meas   = delayed_noisy_measurement(P_hidden)
```

第一阶段优化变量是沿航迹切向地速参考 `v_ref`，第二阶段加入上下桨转速比参考 `eta_ref`。主目标仍为固定任务时域内平均电功率最小，同时满足轨迹、姿态、速度和执行器约束。名义模型、隐藏对象和在线测量的信息边界见 [`decisions/ADR-004-power-map-information-boundary.md`](decisions/ADR-004-power-map-information-boundary.md)。

### 0.6 验证与测试总体流程（四步递进验证，2026-09-04 新增）

针对"仓库产出大量由 AI 代理完成、人工难以逐行验证闭环逻辑"的现实约束，全部后续验证按以下四级递进组织。每级只在前一级放行后启动；任何一级不得跳级引用下一级结论，也不得把低级别结果写成高级别结论（与 §2 约束 5/6 同源）。

| 级别 | 名称 | 内容 | 对应仓库里程碑 | 放行条件 |
|---|---|---|---|---|
| V1 | 桌面模型仿真（纯软件） | AI 生成的 Plane 模型、环境模型与算法在统一 Harness 中闭环运行：接口契约测试 + Toy Example + 场景/种子矩阵 | R1--R4、M0--M3、`harness` | 契约与配对验收全绿；同种子一键复现；独立验收会话复核 |
| V2 | 半物理仿真（HIL/SITL） | 真实飞控计算机接入仿真环境，算法与安全层运行在目标硬件或 PX4 SITL 中 | M4 第 3 条 | SITL/HITL 接口与纯 Simulink 接口一致；M0--M3 对比复跑不退化 |
| V3 | 地面物理验证 | 禁飞期间地面架设（倒扣飞机模拟升力、绑缚测试）与台架数据采集，回灌校准 Plane 参数 | M4 第 4/5 条、P 线校准入口 | "台架数据→清洗对齐→参数辨识→仿真校准→留出验证"闭环成立；参数来源从 `proxy` 升级为 `calibrated` |
| V4 | 实飞验证 | 禁飞解除后真实飞行报备与数据采集，复验 V1--V3 结论 | 后续（另行立项） | 飞行日志回放与仿真口径一致；安全链零误触发；结论以实测来源标志发布 |

**复杂系统验证方法论**（贯穿 V1--V4，对应"物理开发底层不可见"的管理手段）：

1. **接口与架构管理**：不逐行审计 AI 代码，而是管住三件事——接口（接口字典 0.3 冻结为 1.0 后任何改动走 ADR）、架构分区（§1 五条工作线互不越界、Mock 可替换）、结果验证（MOP/MOE 配对评价 + 一键日志）。
2. **Toy Example 测试案例**：把场景矩阵中最小、解析可预期的案例固化为标准层级，任何模型/算法改动先过 Toy Example 再进全场景矩阵。建议首批登记：
   - T1 零风直线：`v_air ≡ v_ground`，P(v) 单谷且最优速度解析已知（PL-B 零风恒等门槛的直接演示化）；
   - T2 恒风圆周：`v*(t)=−q+sqrt(q²+V*²−|w|²)` 解析调度可预期（`wind_field_sched` 解析解）；
   - T3 正弦/双正交风：功率曲线平移周期与拍频可预期（任务4/5 口径）；
   - T4 阶跃/边界：`v_ref` 限速、`eta_ref` 饱和与安全回退时序可预期（M0-B/M2 故障注入口径）。
   各模块既有 `tests_*` 已具备雏形，统一以 T1--T4 登记进 `docs/architecture/05_verification_traceability.md`，期望值写死在验收脚本中。
3. **证据治理**：沿用 ADR-003 分层判定与 `ACCEPTANCE_AUTOMATION_RULES.md`；AI 产出一律经独立验收会话（换会话/换执行者）复核后才可放行——M2 十轮与 M3 第一轮 PARTIAL 的既有教训。

V1 是当前全部工作的所在级；V2--V4 在本文件中只冻结接口与放行条件，不预支结论。

## 1. 项目分工与总体闭环

本项目分为五条可并行推进、通过固定接口汇合的工作线：

| 工作线 | 负责对象 | 当前归属 | 产出 |
|---|---|---|---|
| 优化算法线 | ESC、速度与转速比协同策略、后续 RL | Git 仓库协作成员 | 可调用的慢层决策模块 |
| Environment / 场景线 | 任务路径、风真值、风测量退化、场景与种子 | 王健祺已有较多资产，最终归属待组内确认 | `PathCommand`、`WindSample`与场景清单 |
| Control / 飞控平台线 | 速度与姿态快层、X8 控制分配、安全回退、PX4/Simulink 主模型 | 叶安 | 稳定可控的飞行与执行器闭环 |
| Plane / 仿真物理建模线 | 风与空地速换算、阻力/圆周运动、速度与转速比执行动态、联合功率及电池代理 | 建议负责人：霍奕茗（待组内确认） | 可替换、可标定的物理对象与统一状态反馈 |
| Evaluation / 集成线 | 公共适配器、Harness、MOP/MOE与证据 | 周航正统筹，指标资产由王健祺维护 | 公平比较、一键运行和可视化 |

各条线不靠复制同一份模型并行开发。算法线只调用接口；Environment和Plane先作为独立 MATLAB/Simulink 组件开发和验收；Control线继续由叶安维护 `models/px4_x8/*.slx`；Evaluation按接口提供Mock和统一场景。Plane单元通过后，再由Control线负责人按接口接入当前开发模型。

目标闭环如下。优化算法**不直接写八路 PWM**；八路指令由飞控与受约束分配器产生。

```text
Scenario/Path：轨迹、任务时长、约束
Environment：WindTruth / WindMeasurement
        ↓
慢层算法：v_ref、eta_ref、模式
        ↓
接口与安全层：范围检查、冻结、基线回退
        ↓
Control：速度控制 / 姿态飞控 / X8 控制分配
        ↓
Plane：执行动态 / 风与空地速 / X8 动力学 / 联合功率对象
        ↓
地速、空速、姿态、PWM、RPM、功率、能耗、SOC、约束标志
        └────────────────────────────→ 慢层算法
```

真实台架或飞行数据的正确用途是校准仿真对象，而不是直接替代仿真结果：

```text
真实数据 → 清洗/时间对齐 → 参数辨识 → 更新仿真参数
        → 仿真验证算法 → 台架/SITL/飞行复验
```

## 2. 不可违反的架构约束

1. 快层负责稳定：姿态、角速度、解锁、基本限幅与故障保护必须保留。
2. 慢层只输出高层目标：初期为 `v_ref`；M2 起增加 `eta_ref`。不得绕过飞控直接驱动 `PWM1...PWM8`。
3. 同轴比值定义为 `eta = omega_upper / omega_lower`。每一对上下桨的编号、旋向和配对关系必须在接口文档中固定。
4. 每个优化运行都必须可与“固定参考、优化关闭”的基线一一比较。
5. 功率信号必须标明来源：`estimated`（模型估算）或 `measured`（实测/校准）。未经校准的估算功率不能宣称真实节能率。
6. 任何安全条件触发时，优化器冻结并回退至最后安全参考或固定基线；安全层不放在 ESC 内核中。
7. 在没有实机或台架数据前，Plane 线所有功率、阻力、电池和执行器参数均标为 `proxy` 或 `estimated`，不得写成已标定物理量。
8. 世界坐标系统一使用 NE 平面；空速定义为 `v_air_ne = v_ground_ne - wind_ne`。风场由 Wind 模块提供，Plane 负责使用，Control 不重复实现风场或功率公式。

## 3. 统一接口合同

### 3.1 算法输入（来自平台）

| 信号 | 单位 | M0 | M2 起 | 说明 |

| P1 风与运动学 | 接入 `wind_ne`，计算地速/空速；直线和固定半径圆周轨迹，输出相位、切向量和径向误差 | 独立运动学对象与零风/顺逆风测试 |
| P2 执行与动力学 | 为 `v_ref`、`eta_ref` 增加有限响应、变化率和饱和；圆周场景显式计算 `a_c=v^2/R` 及姿态需求 | 阶跃、边界和圆周需求测试 |
| P3 联合功率对象 | 建立 `P(v_air, eta; theta)` 代理并积分能量；与现有速度/转速比单变量切片对齐 | 功率对象、参数表、切片与敏感性图 |
| P4 电池与适配器 | 增加简化电压/SOC，统一 `reset/step` 适配器、日志和约束标志；保留日后台架数据校准入口 | 可由 ESC、解析调度、RL 和 Harness 共用的 Plane API |

建议最小接口：

```text
输入：t, dt, v_ref, eta_ref, wind_ne[2], path_command, mass, battery_config
输出：v_ground_ne[2], v_air_ne[2], eta_actual, attitude, yaw_rate,
      motor_pwm[8], motor_rpm[8], P_e, E_e, soc, path_phase,
      radial_error, constraint_flags, power_source
```

验收门槛：

1. 零风时空速等于地速；顺风、逆风的符号和空速变化方向正确。
2. `v_ref` 和 `eta_ref` 不发生瞬时跳变，且变化率、边界和饱和标志可复现。
3. 圆周速度提高时 `v^2/R` 与所需倾角方向正确；固定半径一周后相位闭合。
4. `P(v_air, eta)` 的速度切片与转速比切片能退化到现有代理基线；`E_e` 与 `P_e` 数值积分一致。
5. 所有输出带单位、时间戳/有效性和来源；优化器不能读取完整曲面、真实最优点或未来风。
6. 在未标定阶段只报告代理模型结果；不宣称真实 X8 节能、续航或安全结论。

当前交付：`models/plane` 与 `models/px4_x8/+x8phys` 的独立 MATLAB 代理及适配器已实现；P0 静推分档拟合门槛和 P1--P4 对象/接口契约测试已通过。`models/plane` 按接口字典 0.3 将 PathCommand、WindSample 和 ControlCommand 分离，物理对象只从 WindSample 读取真风。`+x8phys` 使用 PAW 40x13.1R 静推数据的 `T=0.08643*n^2`、`P_e=0.34467*n+0.0289367*n^3`、`KV=76.64 rpm/(V*throttle)` 拟合，以及 ZE12070117A-024Ah 电芯的 OCV/容量/内阻量级。静推数据只覆盖空速 0 且约 225--1140 rpm，7S1P、电机动态、非零空速桨效应和整机阻力仍是可覆盖的 `proxy`，不能据此作真实节能或飞行安全结论。`run_x8phys_acceptance`、`run_plane_acceptance` 已通过；整机 S/P 确认、动态校准和接入同一 PX4 `.slx`/Harness/MeasurementAdapter 仍待完成。
