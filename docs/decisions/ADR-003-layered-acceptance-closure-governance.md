# ADR-003：分层验收与问题关闭治理

日期：2026-09-03
状态：**Proposed**
决策负责人：项目组；架构归口为周航正

项目组：周航正、霍奕茗、于跃、叶安、王健祺
提案与文件负责人：叶安
决策记录整理：Codex
技术依据：M2 第一至第九轮独立验收、修复报告与提交历史审计
审核：待项目组讨论、待周航正架构复核、待指导教师确认
AI协助：Codex（历史归类、治理条款与草案整理）

## 一句话说明

项目验收应分别判定功能实现、验收基础设施、环境限制和文档证据；问题只有在原始复现、针对性负向和既有回归三类证据齐备后才能关闭，新增威胁模型不得倒推为既有核心功能再次失败。

## 背景

M2 的多轮复验表面上经历了多次“关闭—重新打开”，但提交历史和数值证据表明，后半程的主要变化集中在验证器、分段证据、manifest、崩溃重试和日志驱动，而不是 `air_spare.slx`、eta 分配器或 ESC 内核。S1/S2/S3 数值与双链哈希连续多轮稳定，验收基础设施则随着威胁模型扩大持续增加能力。

历史中同时存在五种不同现象：原修复没有真实覆盖错误路径、新增验证器自身违反状态契约、新增 staged/manifest/attempt 机制带来新的证据缺口、独立负向探针发现潜伏问题，以及 MATLAB R2022b 原生堆损坏造成的环境失败。若不分层记录，后续协作者会把“验收器 PARTIAL”误读为“M2 核心未完成”，或把更强的新检查倒推为历史功能证据全部无效。

`docs/ACCEPTANCE_AUTOMATION_RULES.md` v1.7 已在 M2 平台线内给出可执行规则。本 ADR 仅提议是否将同一治理方式提升为全项目共同规则；在项目组接受前，不改变其他模块当前已接受的验收合同。

## 提议决策

若本 ADR 被接受，全项目采用以下治理方式：

1. 每份阶段验收分别报告功能实现、验收基础设施、环境限制和文档证据四层结论。
2. 新发现标注为真实回归、修复不完整、新增基础设施缺陷、潜伏问题新发现或环境限制，不再用单一“又坏了”描述。
3. 缺陷关闭必须具备原始复现、针对性负向、既有回归三件套；新增验证机制至少有一个独立 oracle，不能只用自身最终 PASS 自证。
4. 每轮开始前冻结合同、目标问题、矩阵范围和停止条件。执行中出现的新威胁模型进入新编号和新规则版本，不静默扩大当轮结论。
5. 目标层无开放 P0/P1、冻结合同整批通过、三件套齐备且剩余限制已登记时，该层可以停止并标记 CLOSED/VALIDATED；禁止“完全闭环”“永不失败”等无限全称措辞。
6. 当前状态只在 `docs/DEVELOPMENT_STATUS.md` 维护；详细证据进入 `docs/evidence/`，过程进入 `docs/worklog/`，本 ADR 不复制动态结果。

## 不在本提议范围内

- 不改变 Wind-Plane-Control 公共字段、M2 接线或算法因果边界；
- 不改变现有数值门槛和场景协议；
- 不要求其他模块因 M2 验收器的新负向 case 自动退回；
- 不宣称环境级 MATLAB 堆损坏已经消除；
- 不授权未负责模块的成员直接修改其算法实现。

## 备选方案

### A. 只保留每轮验收报告，不增加治理规则

优点是文件改动最少；缺点是换 agent、换成员或上下文压缩后容易再次丢失“功能层与基础设施层分开”的边界，无法形成统一关闭标准。

### B. 把所有新缺陷都视为阶段整体退回

形式最保守，但会把日志编码、manifest 篡改或环境崩溃错误地等同于算法数值回归，导致路线和职责判断失真。

### C. 分层判定与版本化关闭规则（本提议）

保留严格负向验收，同时限定结论影响范围；既不掩盖基础设施缺陷，也不无证据推翻稳定的核心功能。

## 影响

正面影响：验收报告更容易比较；问题关闭依据可复查；新增威胁模型不会造成历史结论语义漂移；项目管理可以知道真正阻塞的是算法、证据链还是环境。

代价：报告需要多写四层判定和问题类型；验收前需要冻结矩阵与停止条件；新增验证基础设施时必须准备独立负向 oracle。

## 采用与复审

当前状态为 Proposed。建议由项目组和架构归口人确认以下两点后决定是否 Accepted：

1. 四层判定是否适用于 `modules/`、`harness/`、`models/` 和 `integration/` 全部工作线；
2. “无开放 P0/P1 + 三件套齐备”的停止条件是否作为项目统一验收门。

若接受，仅把本 ADR 状态改为 Accepted，并在 `AGENTS.md` 增加入口链接；若要求调整，保留本草案历史并记录复审意见，不静默改写提出时背景。
