## 3. 修复内容

### 3.1 F2：可核验搜索中心（内核重放）+ 统一 [192,240)

- 新增 `m3_replay_eta_center.m`：以归档测量（PeE/eta_act/sat/硬标志/计划）驱动冻结的 ratioesc 内核逐步重放，镜像 `m2_eta_esc` 的 m3/esc 分支（hold 发布干净中心、lastReference 同步、reinitialize/warmup=ceil(1/fTs) 语义）。经源码核实 `esc_step` 的 actualRatio 仅参与有效性判定（不进梯度），重放输出与归档 el(:,2) 取值无关，保真比对只对 el(:,1)。
- `m3_eval_arm`：收敛段输入由候选参考（中心+抖动，周期末样本被抖动相位污染）改为重放中心；保真门 maxDiff ≤ 1e-12——非自洽证据（相位反例、死搜索、篡改候选、NaN 候选）一律硬失败；convMask 对 m3/esc 均显式 `te2 ∈ [192,240)`（961 点错一拍消除；末搜索段恰 960 点 = 12 整周期）。
- `m3_eval_convergence` 判据语义未动：合同 §6.4"周期末中心序列单调趋近"在中心输入下按字面成立（此前把"候选的周期末"误当"中心的周期末"）。
- 单测 B8：交替周期中心（均值 1.0045 合格、相邻回退 0.009 > 5e-3）拒收；961 点长搜索段按尾部 960 点评分（首样本污染不入窗）。

### 3.2 F3：姿态限幅全臂硬判

`m3_eval_arm` 增加 `attLimitMax = max(bit3)`（t≥0.05 基线，与 hardMax 同基）并入所有臂的 r.ok。名义臂原有 hardMax==0（含位 3）不变；扰动臂此前仅有 2 s 位 1/2 上限与 yaw/带宽门，现补齐合同 §6.3"姿态限幅内"。真实 14 臂位 3 全零（离线核查），不改判历史数据。

### 3.3 F4：批次治理（规则 v1.7 §2.4–2.9 全量落地）

新增 `m3_batch_contract`（单一固定合同：14 臂、maxAttempts=3、N5/R1 同段；**分段布局参数化**——任何恰好覆盖每臂一次且复现对同段的合法布局均为有效批次）、`m3_batch_init`（batchId+现场提交+现场 sha+干净树门）、`m3_batch_validate`/`m3_batch_locate`（manifest 对源码合同等值：上限字面相等、臂恰好一次、同段规则）、`m3_stage_attempt`（持久计数、同目录临时文件+改名的**原子替换**、坏标记硬失败不重建、超预算在段入口独立拒绝）、`m3_stage_done`（驱动权威新鲜度盖章）、`m3_batch_stage`/`m3_batch_aggregate`（段执行/聚合包装，基线段先行约束）；驱动 `tools/run_m3_batch.ps1`（M2 模式：新鲜度标记权威、rc 仅参考、有界重试、GBK→UTF-8 日志、`-Stages`/`-StagedDir` 续用）+ `tools/test_m3_batch_driver.ps1`（9 场景驱动级测试）；`run_air_m3_trials` 增第 4 参 stagedDir（manifest 验证、计数、batchId/attempts/segName/bindingExit 入结果；**段失败不写盖章**并带归档路径报错——失败段按确定性失败走预算，不冒充盖章后崩溃）；`m3_aggregate_batch` 硬化重写；`run_air_m3_boundary` 补结束取证。

聚合器身份语义（如实声明）：**证据生产文件**（trials/合同/evalArm/模型/两适配器）指纹必须与现场逐字节相等；**聚合器自身**是验证工具而非证据生产者，批次后演进以 `aggregateShaDrift` 备案而不作废批次证据（"换验证器"类攻击由"验证器即当前提交源码本身"覆盖：它跑的就是提交里的检查）。批次同一性绑定 = 各段提交（入口与结束）等于 manifest 批次提交 + 生产文件指纹相等；live HEAD 晚于批次提交（如文档提交）不作废证据。
