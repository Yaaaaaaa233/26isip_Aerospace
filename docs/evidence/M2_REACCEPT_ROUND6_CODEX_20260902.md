## 7. 新问题清单

### R6-F1（高）：manifest 的源码绑定为自引用，不能证明 stage 来自当前提交

- 位置：`verify_m2_round4_closure.m:289-290`、`:571-581`、`:588-620`；
- 现状：init 生成 manifest 时读取一次 HEAD 和验证器 SHA；之后每个 stage 的 `done.gitCommit` 直接复制 `manifest.gitCommit`，聚合器只比较两个被复制的值；stage/report 不重新读取 HEAD、不重算验证器 SHA、不检查 dirty 状态；Git 命令失败时还接受 `gitCommit='unknown'`；
- 影响：init 后切换提交、修改验证器或带未提交改动执行 stage，仍可形成看似同源的证据；当前“提交绑定”只能证明文件内部字段一致，不能证明实际执行源码一致；
- 修复条件：每个 stage 独立记录并校验当前 HEAD、验证器 SHA 与 dirty 状态；拒绝 `unknown` 和 dirty；report 再次重算当前值并与 manifest 和所有 done 标记比较。最好把真实执行指纹写入 CSV/done，而不是复制 manifest 声明。

### R6-F2（高）：聚合器未硬断言 CSV verdict 全为 PASS

- 位置：`verify_m2_round4_closure.m:603-620`；
- 现状：`validateStaged` 检查行数、run ID 和 done 标记，但没有 `all(T.verdict == "PASS")`；
- 影响：只要行数和身份字段正确，含 FAIL 行的 stage CSV 仍可进入聚合并打印总 PASS；这违反 `docs/ACCEPTANCE_AUTOMATION_RULES.md` 的“每段硬断言、禁止只打印 FAIL”要求；
- 修复条件：在聚合前硬断言每一行 verdict 为 PASS，并增加篡改一行 verdict 为 FAIL 后 `report` 必须拒绝的负向证明。

### R6-F3（环境/可复现性阻塞）：C5 在第二条长链中重复退出

- 两个独立尝试均在第一条链完成、第二条链中途退出，现象可复现；
- 该现象与仓库已登记的 R2022b 单进程长序列堆损坏风险一致，不能直接归因为 M2 数值或控制算法缺陷；
- 但 C5 明确要求同会话双链，因此在获得完整证据前，39 行总验证器不能作为独立放行证据；
- 建议在不削弱“同会话确定性”目标的前提下缩短单进程累计仿真深度，例如为 C5 设计只覆盖确定性所需的最小链、复用已验证的只读基线结果，或升级/更换 MATLAB 环境后重跑全 39 行。
