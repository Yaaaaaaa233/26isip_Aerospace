## 1. 结论

**第五轮独立验收结论：M2 核心实现与数值链通过，验收自动化部分通过。**第四轮修复后的标准 15 行针对性矩阵在独立 MATLAB 进程中按规定分段重跑，15/15 PASS；同会话背靠背双链、CSV 确定性、persistent fresh 直探及数值抖动门槛均通过。因此 M2 模型、120 s / `[90,120] s` 协议及既有代理模型结论保持放行。

本轮新增发现不推翻上述核心结果，但证明“总验证器与全部状态契约完全关闭”的表述仍然过强：

1. 四个 M2 验收入口只在 `M2_ETA_APPLIED` 为有限值时保存调用者状态；真实错误注入证明 `NaN/Inf` 会被恢复为空值，而不是原值；
2. `report` 阶段没有本次运行 ID、源码提交或 stage 新鲜度校验；在没有执行任何 stage 的情况下，可直接复用旧 CSV/MAT 并返回 PASS；
3. C2 trials 的“归档路径存在”断言实际只检查消息是否含字面量 `injected`，检查项与声明不完全一致。

因此：M3 方案与实现可以继续；但在下一里程碑把该验证器作为放行门之前，应关闭 R5-F1--F3。不得把本轮代理模型数值外推为真实八旋翼节能率、偏航安全或飞控部署结论。

## 6. 问题清单

### R5-F1（中）：调用者状态快照错误地过滤非有限值

- 位置：`test_m2_eta_esc_unit.m:49`、`run_air_m2_trials.m:37`、`run_m2_session_chain.m:39`、`verify_m2_round4_closure.m:82`；
- 原因：保存条件为 `~isempty(...) && isfinite(...)`；不满足时 cleanup 把原值当作“入口为空”处理；
- 影响：入口声明的“逐域精确恢复”仅对有限标量成立，未登记的隐式前置条件会改变同会话状态；对象侧把非有限值安全降级为恒等 1.0，因此不影响本轮正常数值链；
- 建议：快照时不要用 `isfinite` 过滤；若项目决定非有限调用者状态不属于契约，应在规则、注册表和入口断言中显式写明，并由入口在修改全局量之前硬失败。

### R5-F2（高）：`report` 可复用旧或混批 stage 证据并假绿

- 位置：`verify_m2_round4_closure.m:259-285`；
- 原因：只检查固定文件名存在、verdict 为 PASS、总行数为 15；没有 run ID、提交/源码指纹、生成顺序或时间边界；
- 影响：某个 stage 本次未运行、失败后留下旧文件，或者文件来自不同提交时，`report` 仍可能返回 PASS；这削弱了分段模式作为放行门的可信度；
- 建议：增加 `init`/manifest 步骤生成唯一 run ID；各 stage 写入 run ID、Git 提交、验证器哈希和完成时间；`report` 必须逐文件匹配同一 manifest，且拒绝任何旧批次文件。也可新增一个外层驱动，在独立进程中调度各段并只聚合本次返回的显式路径。

### R5-F3（低）：归档路径断言与声明不一致

- 位置：`verify_m2_round4_closure.m:182-185`；
- 现状：报错文本为“archive path missing”，但代码只断言 `contains(msg, 'injected')`；当前受控失败恰好令 `archiveDir="injected"`，所以通过；
- 建议：断言消息包含 `char(result.archiveDir)`，或让链错误返回结构化 cause/archive 字段后检查该字段，避免依赖巧合字面量。

## 7. 关闭条件与阶段判定

关闭第五轮发现需满足：

1. 四个写 `M2_ETA_APPLIED` 的函数入口统一快照语义；有限、空、NaN、±Inf 在成功与至少一个错误出口的契约均有直接测试；
2. 分段验收引入同批次 manifest，`report` 对旧文件、缺段、混提交三类负向场景均硬失败；
3. C2 trials 路径检查改为真实路径/结构化字段检查，并有“消息缺路径”负向证明；
4. 重跑 15 行标准矩阵，保持双链 2/2、同会话哈希一致和 `±0.015 pp` 数值抖动口径；
5. `AGENTS.md`、开发状态、路线、接口和模型 README 对“核心 M2 PASS / 验收自动化 PARTIAL”的边界一致。
