## 1. 适用范围与目的

本规范约束**验收自动化基础设施**：`models/px4_x8/` 与各模块的验收入口脚本/函数、验收链、以及它们依赖的全局量与持久状态。日常算法参数调整、文档撰写不受本文档约束。

制定依据是 M2 阶段三轮独立复验（`PROJECT_REACCEPT_CODEX_20260901.md`、`M2_REACCEPT_ROUND2_CODEX_20260901.md`、`M2_REACCEPT_ROUND3_CODEX_20260902.md`）暴露的六类失败模式。每条规则标注来源事故，防止"规则存在但没人记得为什么"。

## 2. 入口结构规范

1. 验收入口**必须是函数**（非脚本），并返回机器可查的结果结构（如 `result.pass`、`result.archiveDir`）。
   来源：R3 根因——脚本变量位于调用者工作区，`onCleanup` 在错误边界不执行；脚本无法可靠交付失败信号。
2. 链式入口（串联多个验收的入口）的**每一段必须硬断言**：失败即 `error`/`assert` 退出并携带归档路径；禁止"打印 FAIL 但继续/正常退出"。
   来源：R2-F2（九场景失败链仍打印 END，自动化假绿风险）。
3. 禁止经共享工作区变量在验收段之间交接结果；一律用返回值或显式输出。
   来源：R2-F2 修复讨论。
4. 多进程分段验收的**聚合必须有同批次 manifest 绑定**：init 生成唯一 run ID + git 提交 + 聚合器自身文件哈希；每段输出必须携带该 run ID 与提交指纹；聚合器必须逐文件校验 manifest 一致性，对旧批次文件、缺段、混提交三类场景硬失败，且三类负向证明必须实际执行过。
   来源：R5-F2（report 可复用旧/混批 stage 证据假绿）。
5. manifest 的源码指纹**必须在每个取证点独立现场重取**（init、每段开始、每段盖章、聚合时），禁止复制 manifest 或其他时刻的值；git 取证失败时**禁止 'unknown' 占位**（硬失败）；**脏工作树硬拒绝**（含未跟踪文件，取证命令必须显式指向仓库根、不依赖进程工作目录）；聚合时必须再次现场重算并拒绝跨提交/跨版本批次。证据无法绑定到提交就不是证据。
   来源：R6-F1（manifest 提交/哈希只在 init 取一次、stage 直接复制、接受 'unknown'、不查 dirty，换提交或改验证器仍可形成看似同源的证据）。
6. 分段聚合器**必须对每份 stage 结果的每一行 verdict 硬断言为 PASS**（或显式声明的等价终态）；只校验行数/runId/文件存在而放行 FAIL 行属违规。"篡改一行 verdict 为 FAIL 后聚合器必须拒绝"的负向证明必须实际执行。
   来源：R6-F2（validateStaged 只查行数/runId/done，含 FAIL 行的 CSV 仍可聚合出总 PASS）。
7. **阶段进程崩溃重试语义（环境缺陷的受控韧性）**：对已登记的环境级原生崩溃（本机 R2022b 堆损坏，崩溃深度与位置不定，含"仿真全部完成后、阶段盖章前"与"盖章后进程退出时"两种无害/有害窗口），批次驱动**允许**对某阶段重试，但必须同时满足：(a) 重试仅当该次尝试**未产出新鲜完成证据**（done 标记/新归档目录的时间戳晚于该次尝试开始时刻；**退出码仅为参考信号**——已观测 matlab 启动器在子进程堆损坏死亡时仍以 0 退出，活例 `results/batch_runs/20260902_225209` c2clean，故 rc=0 无新鲜证据同样按可重试失败处理，绝不放行）；(b) 重试是**从段入口的完整重执行**，禁止从任何进程内部分状态续传（时间戳归档天然杜绝混用）；(c) 重试次数**有上界**（上限固化于 init 写入的 `manifest.maxAttempts`，当前为 3，并与入库驱动 `tools/run_m2_batch.ps1` 的 `-MaxAttempts` 缺省保持一致；验证器在段入口独立拒绝超预算执行，不得只写在文档或仓库外脚本中），不得用于熬过真实断言缺陷——确定性失败重试满额后必须中止批次并保留全部尝试日志；(d) 每次段入口必须递增**持久的 `<stage>.attempts` 计数器**（存于 gitignore 的 staged 目录，不影响源码绑定脏树门），完成尝试把计数写入 `done.attempts`，聚合输出逐段打印，证据文档必须如实报告实际尝试数与任何崩溃尝试；(e) done 标记已写出后的进程退出崩溃**无害**（证据已原子完成），后续校验照常进行；(f) **attempt 记账是硬断言证据而非装饰**：report 的 staged 校验必须硬拒绝 `done.attempts` 缺失、非有限正整数、超过 `manifest.maxAttempts`、或与 `<stage>.attempts` 持久标记不一致的任何组合，且"缺字段 / 0 / NaN / 非整数 / 超上限 / 标记不一致"六类负向证明必须实际执行；(g) **计数器写入必须原子替换**（同目录临时文件 + 重命名），使任意原生崩溃窗口至多留下旧值或新值、绝不留下截断标记；蓄意或损坏（空/非数值）标记仍硬失败 `BadAttempts`，不得自动重建（防篡改）；(h) **批次驱动必须入库**（`tools/run_m2_batch.ps1`）并配套驱动层测试（`tools/test_m2_batch_driver.ps1`）：无 done 的非零退出重试、有新鲜 done 的退出崩溃不重试且批次继续、确定性失败重试满额中止并保留全部日志，三类行为必须在验收前实际执行通过。
   来源：R7-F1（第七轮复验 c5 两条最小链完成、归档哈希一致，但进程在链完成与阶段落盘之间原生崩溃，c5.csv/c5.done.mat 未生成；历史崩溃深度 4/8/45 次仿真不等，最小双链 8 次仿真后仍中招——崩溃点随机，代码逻辑无法免疫，只能受控韧性 + 诚实记账）；R8-F1/R8-F2/R8-F3（第八轮篡改探针：`done.attempts=4`、marker=1 仍聚合 42/42 PASS——打印不等于断言；有界重试驱动仅存于仓库外临时脚本，上限声明不可审计；计数器截断写存在窗口性损坏风险）（`M2_REACCEPT_ROUND8_CODEX_20260902.md`）。
8. **staged manifest 是证据，不是权威**：批次合同（阶段集合与顺序、唯一性、各段声明行数、attempt 上限）必须在验证器源码中有**单一固定合同**（如 `expectedManifestContract()`，init 与 report 共用），init 从它写入 manifest；每个段入口与 report 必须**硬断言 staged manifest 与该源码合同等值**（对上限是等值而非"≥1 可用"，对阶段集合是名单/数量/顺序/唯一全等，对声明行数是逐字段全等且总数等于合同值）。禁止以 staged manifest 自身定义要校验的范围——否则协同篡改（提高上限并同步 stamps/marker、或删减阶段与声明行）即可伪造 PASS。"提上限（stamps 自洽）/删阶段与声明行/增或重复阶段（须配齐 csv/done/marker，证明拒绝来自合同检查而非缺文件）/改声明行数"四类负向证明必须实际执行，且必须断言错误落在合同检查本身（错误 ID 专属于合同断言），不得被旁因失败覆盖。
   来源：R9-F1（第九轮协同篡改探针：`manifest.maxAttempts` 3→4 且 done/marker 同步改为 4 后 report 仍 48 PASS；从 manifest 删除 c5 与其声明行后仍 44 PASS——验证的是"stage 证据是否符合当前 manifest"，却从未验证"当前 manifest 是否仍等于提交中定义的批次合同"）（`M2_REACCEPT_ROUND9_CODEX_20260903.md`）。
9. **批次日志编码必须无损**：驱动捕获原生命令（MATLAB -batch）控制台输出时，必须按该命令**实际输出编码**显式解码后再写 UTF-8 日志（本机 R2022b 管道输出为系统 ANSI 代码页，2026-09-03 探针实证原始字节为 GBK），禁止依赖会话控制台编码 ambient 状态；驱动层测试必须包含**非 ASCII 内容的往返断言**（日志含原文且零 U+FFFD）。注：MATLAB 输出编码属机器/区域设置，跨机器复跑时以原始字节探针复核为准。
   来源：R9-F2（第九轮 7 份阶段日志中 6 份的中文路径/警告全部损坏为替换符，英文与数值仍可审计；修复探针证明按 ANSI 页解码后 fprintf 与本地化 warning 路径均无损往返，端到端经驱动捕获函数复验）。

## 3. 全局量状态协议

1. 任何写全局量的验收入口必须实现"**快照 → 规范化/使用 → onCleanup 恢复**"，恢复须在成功路径与错误路径都执行。该模式只在**函数帧**内可靠；脚本入口写全局量视同违规。
   来源：R1-F2（单元测试污染全局）、R2-F1（试验自身遗留状态）、R3-F1/F2（脚本错误路径不恢复）。
2. "恢复调用者状态"与"建立安全前置条件"是两个需求：测试类入口做前者；链式验收入口入口处必须额外做**规范化**（设为安全恒等缺省），不假设调用者状态干净。
   来源：R2-F1 复现（第二轮 §4）。
3. 全局量必须先登记（§7 注册表）再引入：登记 owner、全部读写者、恢复契约与缺省语义。
4. 已知限制必须登记：遗留脚本入口（M0-C/M1）的全局恢复在错误路径不保证，见 §7 状态列。
5. **快照-恢复契约是 exactly-as-found，含非有限值**：不得用 `isfinite` 等条件过滤快照（NaN/Inf 会被悄悄降级为空值）；恢复校验用 `isequaln`。有限/空/NaN/Inf 四态在成功与至少一个错误出口的恢复都必须有直接测试；若项目决定某类值不属于契约，必须在规则、注册表与入口断言中显式声明并在修改全局量之前硬失败。
   来源：R5-F1（isfinite 过滤使 NaN/Inf 调用者状态被恢复为空）。

## 4. 错误路径实跑规则

1. 关于清理、恢复、确定性、降级等**运行时行为**的任何声明，只能以真实注入失败的测试为证；代码审查、正常路径重跑不能关闭"错误路径"类发现。
   来源：R3-F3（第二轮以"代码审查 + 正常重跑"关闭错误路径，被第三轮真实注入推翻）。
2. 验收入口应提供**可控、非破坏性的错误注入钩子**（缺省不激活），使每个断言出口都能被真实触发一次；钩子不得改变缺省行为。
3. 修复验证必须覆盖"**入口状态 × 退出路径**"矩阵。矩阵范围 = **与本次修复缺陷类别相关的全部组合**（而非无边界的一切组合）；证据文档必须附矩阵表，**逐行列明实际执行的 case（入口状态 × 出口），声明行数与实际执行行数一致**。措辞与矩阵一致：执行了多少组合就只能宣称多少，不得使用"全矩阵/完整覆盖"等超出实际行数的表述；若未覆盖某组合（如全部入口状态 × 全部出口），必须命名为"针对性矩阵"并列明未覆盖组合。
   来源：三轮系统性根因——每轮验证范围等于上一轮报告的复现范围；R4-F3（10 行针对性矩阵被表述为"完整笛卡尔覆盖"）。
4. **"同会话"类证据在环境受限时允许收缩为最小充分集，但必须显式改口径**：收缩后的集合仍须完整证明该证据存在的目的（如脏会话复用、同会话确定性、门槛对照），被收缩掉的场景须由其他单进程阶段覆盖或登记为未覆盖；验证器声明、矩阵行标签与证据文档三处必须同步写明收缩边界与未覆盖组合，禁止沿用全量措辞；环境限制解除后应补跑全量并登记。
   来源：R6-F3（C5 全量双链两次在第二条链复现 R2022b 堆损坏退出，最小名义子集双链保持目的证明；全量双链登记为环境限制下的未覆盖组合）。

## 5. 裕量与措辞纪律

1. 数值门槛结论必须同时报告**实测裕量**与**已知复现抖动**；裕量 < 3×抖动时标注"骑线待复验"，不得记为普通 PASS。
   来源：R1-F1（S3 裕量 0.0075pp vs 抖动 ±0.015pp 骑线通过）。
2. 证据文档必须有"验证覆盖范围"小节，列明实际执行过的入口状态与退出路径；结论措辞不得超出该范围。
   来源：两轮勘误（"无需人工清理""成功或异常均恢复"均强于实际验证范围）。
3. "任意会话""完全闭环""一键验收"类全称措辞，在覆盖矩阵未全部执行前禁止写入任何文档。
4. 骑线、抖动、已知的不可复现因素一旦发现，当轮证据必须记录，不得留待复验指出。

## 9. 判定分层与问题关闭治理

本节用于避免把“验收器发现新缺口”误写成“算法或模型再次失败”，也避免修复报告只凭新增机制自身输出便宣布全部关闭。

### 9.1 四层判定必须分开

每份验收报告必须分别给出以下四层结论，不得用一个总 PASS/PARTIAL 覆盖全部语义：

1. **功能实现层**：模型、算法、接口接线和数值门槛是否满足当前冻结协议；
2. **验收基础设施层**：入口、状态恢复、证据绑定、聚合、重试和日志是否能可靠证明功能层结论；
3. **环境限制层**：MATLAB/Simulink、操作系统、硬件或工具链的已知不稳定与未覆盖组合；
4. **文档证据层**：当前状态、证据、接口和路线文档是否使用同一边界与可追溯来源。

某一层出现新问题，只改变该层及其直接依赖层的判定。若功能层的冻结对象、输入和输出证据未发生失败，不得仅因验收基础设施新增缺陷而写成“核心功能退回”。

### 9.2 问题类型必须标注

新发现至少归入以下一种类型，并在报告中说明依据：

- **真实回归**：既有通过用例在相同冻结合同和环境下被后续改动破坏；
- **修复不完整**：原始复现或错误路径从未被修复证据真实覆盖，后续执行才证明仍失败；
- **新增基础设施缺陷**：为验收、聚合、绑定或重试新增的代码产生新缺口，但未证明功能实现退化；
- **潜伏问题新发现**：问题此前已存在，因新增负向探针或更强取证才被看见；
- **环境限制**：工具链原生崩溃、退出码失真或资源上限等仓库代码无法直接消除的问题。

“重新打开”必须指向原问题的具体关闭条件；若只是威胁模型扩大，应建立新编号，不得倒推历史功能证据无效。

### 9.3 关闭证据三件套

缺陷只有同时满足以下条件才能标记 CLOSED：

1. **原始复现**：最初失败用例在当前干净提交上按原入口重新执行并通过；
2. **针对性负向**：针对根因的可控失败、篡改或边界 case 被独立 oracle 拒绝，且断言落在预期错误 ID/字段，不被更早的旁因短路；
3. **既有回归**：受影响范围内此前已登记的正向与负向矩阵全部通过，数值结论继续报告裕量与抖动。

新增验证机制不得只用自己的最终 PASS 自证正确；至少一个关闭证据必须来自独立驱动、独立 fixture/玩具副本、受控注入或与实现路径不同的直接检查。

### 9.4 合同冻结、变更与停止条件

- 每轮开始前冻结本轮验收合同、目标问题编号、矩阵范围和停止条件；执行中扩大威胁模型时，新增问题编号并进入下一规则版本，不静默改变当轮“通过”的含义。
- 合同、阶段集合、门槛或证据语义改变时必须升级规则/接口版本，并明确旧证据是否仍适用；只增加更强的基础设施负向检查，不自动推翻同一冻结功能合同下的既有数值证据。
- 当目标层无开放 P0/P1、当前冻结合同整批通过、关闭证据三件套齐备、历史回归矩阵通过，且剩余 P2/环境限制已登记边界时，本轮可以停止并标记该目标层 CLOSED/VALIDATED。
- “停止”不等于宣称不存在任何未来风险。后续出现新威胁模型时按新编号和新版本处理，禁止用“完全闭环”“永不失败”等无限全称措辞。

### 9.5 报告最小结构

独立验收报告至少包含：冻结对象/提交、四层判定、旧问题关闭表、新发现类型、实际矩阵与 attempts、数值裕量与抖动、环境和未覆盖组合、下一轮最小清单。修复报告不得替代后续独立验收。
