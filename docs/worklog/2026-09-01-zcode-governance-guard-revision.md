# 2026-09-01 治理保护机制修订：从分支保护改为规则集+守卫工作流

## 本次做了什么

- **修订 2026-09-01 "顶层治理文件权限保护" 简报中的方案**：原方案（经典分支保护 require PR + code owner review）会把所有非管理员协作者的直推一并拒绝，阻塞"组员用 AI 直接推送模块代码"的日常工作流，已删除该保护规则。
- 改为两层机制：
  1. **分支规则集** `main 分支历史保护`（ruleset id 21990874）：仅禁强推与删除 main，创始人 @Zhoucmd6 永久豁免，**不禁直推**；
  2. **CI 守卫** `.github/workflows/governance-guard.yml`：非创始人推送触及受保护顶层文件时，自动把**这些文件**回退到推送前版本并判红提示，推送中的其余文件正常保留；创始人的推送直接跳过检查。
- 平台限制结论（本次排查确认）：个人账号仓库不可用 push 规则集（`file_path_restriction` 仅限组织仓库），经典分支保护无法按文件放行直推——故按文件强制只能由 CI 守卫承担。

## 关键决策与理由

- 受保护清单不变（AGENTS.md、README.md、.gitignore、docs/COLLABORATION.md、docs/PROJECT_EXECUTION_ROADMAP.md、docs/interfaces/、.github/），CODEOWNERS 与守卫工作流两处各登记一份，调整须创始人同步修改。
- 选择"落地后自动回退"而非"推送前拒绝"：后者在个人仓库只能以禁止直推为代价（平台限制），会阻塞组员 AI 工作流；回退式守卫保证受保护文件的实际状态始终等于创始人版本，同时零阻碍保留团队直推习惯。
- 若未来仓库转入组织名下，可升级为 push 规则集实现"推送前硬拒绝"，本工作流可保留作为双保险。

## 遗留问题 / 风险

- 回退式保护有约一分钟窗口期，期间受保护文件处于被改状态（随后自动恢复）；对"顶层设置最终一致性由创始人保证"的目标足够。
- 组员需知悉：触碰顶层文件的推送会被自动回退并收到错误标注，这不是 CI 故障。
