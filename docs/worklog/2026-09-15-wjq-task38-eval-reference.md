# 2026-09-15 王健祺（ZCode 协助）：任务3.8——平台评价参照修复（滑动电压真下界）

## 起因
用户质疑：同一套算法接入平台 P2 数据源后 MOE/excess 反而优于本地代理——"感觉不对劲"。
诊断实验（3600/9000s，双后端同种子同风，excess 逐秒分解 = 速度失配 miss + 链条偏移 chain）证实：
- 平台 `minPowerTrue` 是**满电 OCV 稳态解析曲线谷底的常数**，而实时链 `plane.step` 按
  **逐拍跌落电压**插值台架分块系数——实测实时链便宜 ~1.0%（3600s）～1.65%（9000s）；
- 恒定参照在平台上不是真下界：26%～90% 的秒数功率"低于理论最低"；
- 名义上最好的 purerl_off 9000s −1.21% = 速度失配 +0.44% − 链条偏移 1.65%；
- 次要真实因素：平台台架曲线谷底更平缓（偏 0.5/1/2 m/s 惩罚 0.35%/1.36%/5.47% vs
  本地 1.72%/4.13%/4.64%）。

## 修复（新模块 `modules/platform_link_38`，3.7 全量继承 + 评价口径修复）
`+w36/make_platform_plant.m`：
- 新增 `local_curveJV(pc,V)` 按端电压重算真值曲线（与 adapter truth() 同式）；
- 构造时建 41 点电压域 `PminNormV` 查找表（满电→截止电压）；
- 逐秒日志 `minPowerTrue` = `PminNormAtV(s.voltage_v)`——随当前电压滑动的真值谷底，
  恢复真下界语义；UI 真值曲线仍为满电口径（显示用）；本地后端零改动。
