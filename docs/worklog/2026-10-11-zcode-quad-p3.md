## 首评与两次勘误（按"先登记后重评"闭环）

1. **首评（L0 口径）G-P1 FAIL = 实质发现**：真值排序 known<sweepcal<openloop，
   L0 估计口径**完全反序**——L0 速度依赖偏差（+19%→+10.7%）使快飞显得更便宜。
   Q 系"D1 升 L1"同一发现的独立复现。数据存档 `quad_p3_firstfire_l0.*`。
   附带两个代码 bug 修复：`min()` 第一输出是最小值不是索引（known 臂被喂了功率
   当速度）；cellfun 误按行取 cell。
2. **估计链升 L1**（§4.3 勘误登记，门槛不动）：`est_model='l1'` 声明系数修正
   （台架映射 − H3 诱导节省 + 废阻地速代理 + aux，全声明值、无真值拟合）——
   P2 清单"估计链重标定"的实现落地。快测验证：偏差 +19.6% → +0.11%（6 m/s 静风）。
3. **接线 bug**：est_model 曾从 runopt 传入但估计器读 config——L1 未生效（数值与
   首评逐位相同暴露）；改走 config 声明通道后重评。

## 终评结果（4 门 PASS + G-P1 如实 FAIL）

- **E1 扩带（前提成立）**：三风相位命令谷 v*=4/6/6 m/s、Pmin < 悬停，谷随风移动；
  10–14 m/s 出现推力/转速天花板平台（H9）。
- **排序结论（真值口径）**：known 38.50 < openloop 41.14 ≈ sweepcal 41.14 Wh
  （MOE 1.000/0.936/0.936）。oracle 收益 6.87% 存在；**本配置 sweepcal 回收 ≈0%**
  （与 openloop 差 0.3 J）。分相位：静风段赢 14 W、顺风段输 13 W，相消。
- **G-P1 FAIL（结构性）**：估计口径给出 +14.5pp 假赢面（sweepcal 的 Ehat 反而比
  oracle 低 5%）。根因=真机传感器集（无风测量）下 L1 的地速代理残差 ±5–10% 且依
  轨迹组成而变（+8.7%/−5.7%/+6.1%），亚 pp 级排序在估计口径下不可判定。
- **估计器残差主动误导寻优**（关键发现）：顺风段地速代理高估废阻 → sweepcal 的
  P̂ 拟合把高速命令看得过贵 → vBest 走到下限 4（真值命令谷在 6）→ 顺风段反输。
  估计器不只是评估口径问题，是算法输入质量问题。
- 控制现实性涌现：cmd→实飞偏移 −3/+5 m/s（cmd 8→实飞 5/8/13，解析平衡点吻合）
  ——寻优问题本质在命令空间，命令→(实飞,功率) 映射随风变。
- 敏感性：s1 常数偏差磨损恒 0（Q1"常数偏差无害"复现）；s2 ±0.7 档 ≤0.05pp、
  ±1.4 探针档 1.72pp（可翻排序）。
- G-P2 因果白名单逐调用断言全过；G-P3 RERUN 逐位；G-P4 门内。

## 待叶安裁决（P3 红灯出口）

1. 估计器路线：偏差平坦化标定 / 增风测量通道 / 评估只用真值口径；
2. sweepcal 配置改进：探测窗/周期、命令空间直接建模（或换更强寻优器）。
裁决前估计口径数字不得作为验收结论引用（§4.4 结论边界）。
